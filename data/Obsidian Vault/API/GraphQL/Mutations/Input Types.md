## 1. Why use an input type

Until now, our mutation accepted separate arguments:

```GraphQL
type Mutation {
    createBook(
	    title: String!, 
	    author: String!
	): Book!
}
```

and our Java method looked like:

```java
@MutationMapping
public Book createBook(
    @Argument String title,
    @Argument String author
) {
    return bookService.create(title, author);
}
```

This works well for simple mutations. But as the number of fields grows, passing every value separately becomes cumbersome.

Imagine our `Book` now contains:

```
title
author
category
isbn
description
year
```

Without an input type, the mutation becomes:

```
type Mutation {
    createBook(
        title: String!
        author: String!
        category: String!
        isbn: String
        description: String
        year: Int
    ): Book!
}
```

The Java method would also need many arguments:

```java
@MutationMapping
public Book createBook(
    @Argument String title,
    @Argument String author,
    @Argument String category,
    @Argument String isbn,
    @Argument String description,
    @Argument Integer year
) {
    // ...
}
```

Instead, we can group the data into one object:

```GraphQL
type Mutation {
    createBook(input: CreateBookInput!): Book!
}
```

This is similar to using a request DTO in a REST API.

```
REST                         GraphQL

@RequestBody                 @Argument
CreateBookRequest            CreateBookInput
      │                            │
      └── structured data ─────────┘
```

## 2. Input Type

GraphQL has a special type called `input`. 

```GraphQL
input CreateBookInput {
    title: String!
    author: String!
}
```

We can then use it in our mutation:

```GraphQL
type Mutation {
    createBook(input: CreateBookInput!): Book!
}
```

The complete schema becomes:

```
type Query {
    books: [Book!]!
}

type Mutation {
    createBook(input: CreateBookInput!): Book!
}

input CreateBookInput {
    title: String!
    author: String!
}

type Book {
    id: ID!
    title: String!
    author: String!
}
```

## 3. Type vs Input

Why can't we just use `Book` as the input? 

```GraphQL
type Mutation {
    createBook(book: Book!): Book!
}
```

GraphQL does **not** allow ordinary object types to be used as input values.
GraphQL distinguishes between **output types** and **input types**.

Our output object is:

```
type Book {
    id: ID!
    title: String!
    author: String!
}
```

Our input object is:

```
input CreateBookInput {
    title: String!
    author: String!
}
```

This separation is useful because the structures frequently aren't identical.
For example, when creating a book, the client shouldn't provide id, because the server generates it.

```
CreateBookInput
├── title
└── author

Book
├── id        ← generated by server
├── title
└── author
```

## 4. Complete example

schema.graphqls

```
type Query {
    books: [Book!]!
}

type Mutation {
    createBook(input: CreateBookInput!): Book!
}

input CreateBookInput {
    title: String!
    author: String!
}

type Book {
    id: ID!
    title: String!
    author: String!
}
```

CreateBookInput.java

```java
package com.example.graphql.model;

public record CreateBookInput(
    String title,
    String author
) {}
```

Book.java

```java
package com.example.graphql.model;

public record Book(
    Long id,
    String title,
    String author
) {}
```

BookController.java

```java
package com.example.graphql.controller;

import com.example.graphql.model.Book;
import com.example.graphql.model.CreateBookInput;
import com.example.graphql.service.BookService;
import org.springframework.graphql.data.method.annotation.Argument;
import org.springframework.graphql.data.method.annotation.MutationMapping;
import org.springframework.graphql.data.method.annotation.QueryMapping;
import org.springframework.stereotype.Controller;

import java.util.List;

@Controller
public class BookController {

    private final BookService bookService;

    public BookController(BookService bookService) {
        this.bookService = bookService;
    }

    @QueryMapping
    public List<Book> books() {
        return bookService.findAll();
    }

    @MutationMapping
    public Book createBook(
        @Argument CreateBookInput input  // Look here
    ) {
        return bookService.create(input);
    }
}
```

BookService.java

```java
package com.example.graphql.service;

import com.example.graphql.model.Book;
import com.example.graphql.model.CreateBookInput;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.atomic.AtomicLong;

@Service
public class BookService {

    private final List<Book> books = new ArrayList<>();

    private final AtomicLong idGenerator = new AtomicLong();

    public BookService() {
        books.add(
            new Book(
                idGenerator.incrementAndGet(),
                "Clean Code",
                "Robert C. Martin"
            )
        );

        books.add(
            new Book(
                idGenerator.incrementAndGet(),
                "Effective Java",
                "Joshua Bloch"
            )
        );
    }

    public List<Book> findAll() {
        return books;
    }

    public Book create(CreateBookInput input) {  // Look here

        Book book = new Book(
            idGenerator.incrementAndGet(),
            input.title(),
            input.author()  // Look here
        );

        books.add(book);

        return book;
    }
}
```
