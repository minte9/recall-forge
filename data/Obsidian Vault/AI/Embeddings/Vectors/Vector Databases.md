## 1. Overview

A vector database stores numerical embeddings and supports similarity searches over them. Unlike traditional databases, which primarily retrieve records using exact conditions, vector databases can retrieve records whose embeddings are semantically similar to a query.

Popular options include Pinecone, Qdrant, Milvus, and PostgreSQL with the pgvector extension. PostgreSQL is particularly useful when an application already uses relational data because vectors and application records can live in the same database.
### How vector search works

User query:

```txt
"How do I build REST APIs with Java?"
```

Embedding model converts query into a numerical vector:

```txt
[0.12, -0.45, 0.78, ...]
```

PostgreSQL + pgvector:

```txt
Finds the most similar stored vectors
```

Ranked documents:

```txt
Spring Boot REST controllers -- 0.91
Java backend development -- 0.86
Python FastAPI introduction -- 0.64
```

A vector record typically contains three elements: an identifier, the embedding itself, and metadata such as document text, category, source, or user ID.

## 2. PostgreSQL with pgvector

The `pgvector` extension adds vector data types and similarity operators to PostgreSQL. It supports exact vector search and approximate indexing methods such as HNSW and IVFFlat.

For our example, we'll use a separate PostgreSQL container with pgvector enabled.
### Docker Compose

Create `compose.yaml`:

```yml
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: embeddings
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    ports:
      - "127.0.0.1:5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

Start PostgreSQL:

```sh
docker compose up -d

docker compose exec postgres 
  psql -U app -d embeddings
```

Enable the extension:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### Creating a vector table manually

For demonstration, create a table with three-dimensional vectors:

```sql
CREATE TABLE documents_demo (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding VECTOR(3)
);

INSERT INTO documents_demo (content, embedding)
VALUES
    ('Java programming', '[0.8, 0.6, 0.1]'),
    ('Spring Boot development', '[0.7, 0.7, 0.1]'),
    ('Mountain hiking', '[-0.4, 0.1, 0.9]');
```

Search for the closest vectors using cosine distance:

```sql
SELECT
    content,
    1 - (embedding <=> '[0.75, 0.65, 0.1]') AS similarity
FROM documents_demo
ORDER BY embedding <=> '[0.75, 0.65, 0.1]'
LIMIT 2;
```

The `<=>` operator calculates cosine distance. Subtracting that distance from 1 produces cosine similarity.

These are illustrative vectors. Real embeddings must be generated by an embedding model, and their dimensions must match the model's output.

### Adding an HNSW index

```sql
CREATE INDEX documents_demo_embedding_idx
ON documents_demo
USING hnsw (embedding vector_cosine_ops);
```

For a tiny dataset, PostgreSQL will generally prefer a sequential scan. HNSW becomes more valuable as the number of vectors increases.

## 3. Spring AI VectorStore

Spring AI provides a `VectorStore` interface that abstracts the underlying vector database. Your Java code can add, search, and delete documents without writing SQL queries for every operation.

Spring AI also integrates with an `EmbeddingModel`, which converts document content and search queries into vectors automatically.

For this lesson, we'll use OpenAI's `text-embedding-3-small` model, which produces 1536-dimensional embeddings by default.

## 4. Storing, Querying, and Updating Embeddings

### DocumentService.java

The service uses Spring AI's `VectorStore` interface to store documents, retrieve similar documents, and delete existing records.

```java
package com.example.vectordemo;

import java.util.List;
import java.util.Map;

import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.stereotype.Service;

@Service
public class DocumentService {

    private final VectorStore vectorStore;

    public DocumentService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void addDocument(String text, String category) {
        Document document = new Document(
            text,
            Map.of("category", category)
        );

        vectorStore.add(List.of(document));
    }

    public List<Document> search(String query) {
        return vectorStore.similaritySearch(
            SearchRequest.builder()
                .query(query)
                .topK(3)
                .build()
        );
    }

    public List<Document> searchByCategory(
            String query, String category) {

        return vectorStore.similaritySearch(
            SearchRequest.builder()
                .query(query)
                .topK(3)
                .filterExpression(
                    new org.springframework.ai.vectorstore.filter
                        .FilterExpressionBuilder()
                        .eq("category", category)
                        .build()
                )
                .build()
        );
    }

    public void deleteDocument(String id) {
        vectorStore.delete(List.of(id));
    }
}
```

When calling `vectorStore.add()`, Spring AI generates an embedding using the configured `EmbeddingModel` and stores it alongside the document content and metadata.

When calling `similaritySearch()`, Spring AI embeds the query and searches for the closest stored vectors. Metadata filters can restrict the search to matching categories.

### DocumentController.java

We'll expose simple REST endpoints to test the integration.

```java
package com.example.vectordemo;

import java.util.List;
import java.util.Map;

import org.springframework.ai.document.Document;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/documents")
public class DocumentController {

    private final DocumentService service;

    public DocumentController(DocumentService service) {
        this.service = service;
    }

    @PostMapping
    public Map<String, String> add(
            @RequestBody AddRequest request) {

        service.addDocument(
            request.text(),
            request.category()
        );

        return Map.of("status", "created");
    }

    @GetMapping("/search")
    public List<Document> search(
            @RequestParam String query,
            @RequestParam(required = false) String category) {

        if (category != null && !category.isBlank()) {
            return service.searchByCategory(query, category);
        }

        return service.search(query);
    }

    public record AddRequest(
        String text,
        String category
    ) {}
}
```

This controller is intended for local experimentation. In a production application, add authentication, authorization, input validation, and document ownership checks.

### Where exactly is OpenAI used?

In your `application.yml`:

```yml
spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      embedding:
        options:
          model: text-embedding-3-small
```

This configures Spring AI's `EmbeddingModel` implementation to use OpenAI.

You don't explicitly call OpenAI in your Java code because Spring AI handles that internally.

There are two places where the embedding model is used.

**A. When adding a document**

In `DocumentService.java`:

```java
public void addDocument(String text, String category) {
    Document document = new Document(
        text,
        Map.of("category", category)
    );

    vectorStore.add(List.of(document));
}
```

When you call `vectorStore.add()`, Spring AI automatically:

1. Sends the document text to the OpenAI embeddings API.
2. Receives a 1536-dimensional vector.
3. Stores the text, metadata, and embedding in PostgreSQL.

**B. When searching for documents**

```java
public List<Document> search(String query) {
    return vectorStore.similaritySearch(
        SearchRequest.builder()
            .query(query)
            .topK(3)
            .build()
    );
}
```

Spring AI automatically:

1. Sends the query text to the same OpenAI embedding model.
2. Receives a query embedding.
3. Executes vector similarity search in PostgreSQL.
4. Returns the closest documents.
## 6. Updating and Deleting Embeddings

An important distinction is that embeddings represent the content at the time they were generated. If the content changes, the embedding must be regenerated.

A simple update strategy is:

```java
public void updateDocument(
        String id,
        String newText,
        String category) {

    Document updated = new Document(
        id,
        newText,
        Map.of("category", category)
    );

    // PgVectorStore replaces the row for the same ID.
    vectorStore.add(List.of(updated));
}
```

For this strategy, the ID must already belong to the intended document. In a multi-user application, verify ownership before updating it.

## 7. Key concepts to remember

|Concept|Meaning|
|---|---|
|Vector database|Stores embeddings and supports similarity search|
|pgvector|PostgreSQL extension for vector operations|
|`EmbeddingModel`|Converts text into numerical vectors|
|`VectorStore`|Spring AI abstraction for vector storage and retrieval|
|`PgVectorStore`|PostgreSQL implementation of `VectorStore`|
|HNSW index|Accelerates approximate nearest-neighbor search|
|Metadata|Attributes used to organize and filter documents|
|Re-embedding|Regenerating embeddings when source content changes|
